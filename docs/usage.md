# Usage

## Create a Linux project

    cd ~/Projects
    mkproj my_tool

For an existing empty directory, cd into it and run mkproj with no name.
Only missing scaffold files are generated. Live or dirty repositories are refused.

## Inputs and options

Names: 1-64 ASCII characters, starting with a lowercase letter and followed by
lowercase letters, digits, or underscores. Python keywords, uppercase, punctuation,
whitespace, control characters, Unicode lookalikes, and longer names are rejected.
The full target path is limited to 2048 bytes. Invalid input fails before setup.

    mkproj --dry-run --agent=none my_tool
    mkproj --doctor
    mkproj --test
    mkproj --no-global --agent=claude my_tool
    mkproj --no-global --agent=codex my_tool
    mkproj --no-global --agent=none my_tool

Choose one command mode and at most one project name. Duplicate or unknown
options fail. --test and --help take no additional arguments.
--doctor takes only an optional name. --agent accepts exactly claude/codex/none.

Prompt answers accept one ASCII character. Confirmations accept y/n or Y/N.
Agent choice accepts 1-3, Claude model choice 1-8, and effort choice 1-4.
Enter selects the displayed default; invalid and overlong answers reprompt;
EOF aborts. Input is never truncated into a valid choice.

Setup confirms the target, offers a local bare origin, selects an agent if none
was specified, offers optional global setup (default No), and shows a final plan.
New directories are created only after preflight confirmations. Existing origins
are never rewritten and unrelated bare collisions abort without changes.

## Verification and launch

The project .venv interpreter is verified before dependency installation.
Private-path guards and ignore rules are checked before committing only files
generated by this run. Failures retain the project and report the failing phase.
A configured origin is pushed after successful verification. Inspect all push
URLs when configuring an origin with multiple destinations.

Claude launch offers model/effort/bypass choices without changing status settings.
Codex launch uses its existing configuration. --agent=none finishes without
launching either agent. --no-global skips shell/global hook configuration.

## Tests and diagnostics

    bash tests/test-input.sh
    .venv/bin/python -m unittest discover -s tests -p 'test_reliability.py' -v
    mkproj --test
    mkproj --doctor

--test is isolated and never pushes or edits user-global configuration.
--dry-run and --doctor are read-only.
See reliability.md for backups, recovery, failure handling, and guard limitations.
