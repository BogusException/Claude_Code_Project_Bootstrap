# Usage

## Create a Linux project

    cd ~/Projects
    mkproj my_tool

For an existing empty directory, cd into it and run mkproj with no name.
Only missing scaffold files are generated. Live or dirty repositories are refused.

## Inputs and options

Names: 1-64 ASCII characters, starting with a lowercase letter and followed by
lowercase letters, digits, underscores, or hyphens. Hyphens cannot appear at the
end or consecutively (e.g. `my--tool`). Python source directories under `src/`
automatically convert hyphens to underscores (`claude-skill-goal` ->
`src/claude_skill_goal/`). Python keywords, uppercase, punctuation, whitespace,
control characters, Unicode lookalikes, and longer names are rejected.
The full target path is limited to 2048 bytes. Invalid input fails before setup.

    mkproj --dry-run --agent=none my_tool
    mkproj --doctor
    mkproj --test
    mkproj --no-global --agent=claude my_tool
    mkproj --no-global --agent=codex my_tool
    mkproj --no-global --agent=none my_tool

Choose one command mode and at most one project name. Duplicate or unknown
options fail. --test and --help take no additional arguments.
--doctor takes only an optional name. --agent accepts exactly claude/codex/none.

## Non-interactive usage

To create a project without answering prompts (useful in scripts or CI), pipe
newlines to accept all defaults. With `--agent=claude --no-global`, only three
prompts remain (path confirm, bare repo, final proceed) -- all default to yes:

    printf '\n\n\n' | bash /path/to/project-bootstrap/bootstrap.sh \
        --agent=claude --no-global my-project-name

`--agent=claude` skips the agent selection prompt. `--no-global` skips the global
shell/hooks prompt. The three remaining prompts all default to yes, so piped
newlines select each default without manual input.

If `mkproj` is on your PATH:

    printf '\n\n\n' | mkproj --agent=claude --no-global my-project-name

Prompt answers accept one ASCII character. Confirmations accept y/n or Y/N.
Agent choice accepts 1-3, Claude model choice 1-8, and effort choice 1-4.
Enter selects the displayed default; invalid and overlong answers reprompt;
EOF aborts. Input is never truncated into a valid choice.

Setup confirms the target, offers a local bare origin, selects an agent if none
was specified, offers optional global setup (default No), and shows a final plan.
New directories are created only after preflight confirmations. Existing origins
are never rewritten and unrelated bare collisions abort without changes.

## Verification and launch

The project .venv interpreter is verified before dependency installation.
Private-path guards and ignore rules are checked before committing only files
generated by this run. Failures retain the project and report the failing phase.
A configured origin is pushed after successful verification. Inspect all push
URLs when configuring an origin with multiple destinations.

Claude launch offers model/effort/bypass choices without changing status settings.
Codex launch uses its existing configuration. --agent=none finishes without
launching either agent. --no-global skips shell/global hook configuration.

## Tests and diagnostics

    bash tests/test-input.sh
    .venv/bin/python -m unittest discover -s tests -p 'test_reliability.py' -v
    mkproj --test
    mkproj --doctor

--test is isolated and never pushes or edits user-global configuration.
--dry-run and --doctor are read-only.
See reliability.md for backups, recovery, failure handling, and guard limitations.

## Updating existing projects

After upgrading mkproj, update a single project:

    cd ~/Projects/my_tool && mkproj --update

Update every mkproj-managed project under a directory:

    mkproj --scan ~/Projects

See which projects have pending changes without touching anything (exits 2 if any):

    mkproj --status ~/Projects

The update decision for each file follows this table:

- Template unchanged, disk unchanged: skip (up to date)
- Template changed, disk unchanged: apply silently
- Template unchanged, disk changed: skip (keep user edits)
- Both changed: conflict prompt (update / keep / defer / stop)
- File deleted by user: skip permanently
- New file in template: install

Add `--yes` to skip conflict prompts and keep all user edits. Add `--quiet` to
suppress informational output. Add `--verbose` to see every file decision,
including up-to-date skips.

The `.mkproj` file in each project tracks the installed mkproj version,
install/update timestamps, and per-file hash pairs. It is gitignored and
never committed.

Deferred conflicts are saved with status `deferred` in `.mkproj`. Review them
all at once:

    mkproj --pending ~/Projects

## Enrolling an existing project

If you have a Claude Code project (one with `.claude/` or `CLAUDE.md`) that was
not bootstrapped with mkproj, enroll it:

    cd ~/Projects/legacy_project && mkproj --adopt

Adopt never modifies existing files. It only adds missing entries to `.gitignore`
and installs AGENTS.md if absent, then writes `.mkproj` recording the current
state. After adoption, `--update` can install new template files and track
further changes.

## Keybindings

By default mkproj does not touch `~/.claude/keybindings.json`. Pass
`--keybindings` to install or update it from the bundled template:

    mkproj --keybindings my_tool

The template is at `templates/keybindings.json`. mkproj records the installed
hash in `~/.claude/keybindings.json.last-installed-hash` and updates the file
only when the template changes. If you have customized keybindings, do not use
`--keybindings` -- that flag is for machines where you want the managed defaults.
